AI 건축 인허가 매니저 API 키 신청 가이드
=========================================

작성일: 2026-05-27
대상: R.E.D. 팀원

이 문서는 AI 건축 인허가 매니저 개발에 필요한 외부 API 키를 팀원이 동일하게 신청할 수 있도록 정리한 가이드다.


1. 현재 .env에서 사용하는 API 키
-------------------------------

루트 .env.example 기준 현재 프로젝트가 요구하는 키는 다음 5개다.

VWORLD_API_KEY=
ROAD_ADDRESS_API_KEY=
BUILDING_HUB_API_KEY=
LAW_OPEN_API_KEY=
OPENAI_API_KEY=

현재 1차 개발자가 신청하고 동작 확인한 키:

- VWorld API Key
- 도로명주소 API 승인키
- 건축HUB 건축물대장정보 서비스 키
- 국가법령정보 공동활용 Open API 키
- OpenAI API Key

추가로 신청/승인해두면 좋은 API:

- 국토교통부_건축HUB_건축인허가정보 서비스

이 서비스는 기획서상 유사 인허가 이력, 기존 인허가 정보, 프로젝트 상세/이력 확장에 필요하다. 현재 스크린샷 기준으로는 신청자가 이미 승인받은 것으로 보이지만, 다른 팀원도 각자 공공데이터포털에서 활용신청을 해두는 것이 좋다.


2. VWorld API Key
-----------------

용도:

- 지도 표시
- 필지/공간정보 조회
- WMS/WFS 레이어 조회
- 토지이용계획 및 공간규제 레이어 연계

사이트:

https://www.vworld.kr

신청 절차:

1) VWorld 접속
2) 회원가입 또는 로그인
3) 상단 메뉴에서 오픈API 이동
4) 인증키 메뉴 이동
5) 인증키 발급 선택
6) 서비스명 입력
   예: AI 건축 인허가 매니저 개발
7) 활용 목적 입력
   예: 주소/PNU 기반 필지 식별, 지도 표시, 토지이용계획 및 공간규제 레이어 조회를 위한 개발용 MVP 구축
8) 사용할 API 선택
   - 2D 지도 API
   - 데이터 API
   - WMS/WFS 관련 공간정보 API
   - 주소/좌표 검색 관련 API가 있으면 함께 선택
9) 개발 URL 또는 도메인 입력이 필요하면 우선 아래 값을 입력
   - localhost
   - http://localhost:5173
   - http://localhost:8000
10) 발급된 인증키를 .env의 VWORLD_API_KEY에 입력

비고:

- 토지이용계획정보는 현재 별도 폐기/전환 이력이 있어, VWorld 기반 WMS/WFS/속성정보 연계를 우선 기준으로 둔다.
- 지도 화면에서 직접 브라우저 호출을 하게 되면 키 노출 문제가 생길 수 있으므로, 실제 운영에서는 백엔드 프록시 또는 도메인 제한 정책을 함께 검토해야 한다.


3. 도로명주소 API 승인키
-----------------------

용도:

- 도로명주소 검색
- 지번주소 검색
- 주소 정규화
- PNU 변환 전처리

사이트:

https://business.juso.go.kr

신청 절차:

1) 주소기반산업지원서비스 접속
2) 주소정보 API 연계 또는 개발자센터 메뉴 이동
3) API 신청하기 또는 API 목록 이동
4) 검색 API를 우선 선택
5) 서비스명 입력
   예: AI 건축 인허가 매니저
6) 사용 목적 입력
   예: 사용자 입력 주소를 표준주소/지번주소로 정규화하여 PNU 변환 및 필지 식별에 활용
7) 사용 환경은 개발 또는 테스트로 선택
8) URL 또는 IP 입력이 필요하면 로컬 개발 기준으로 입력
   - localhost
   - http://localhost:5173
   - http://localhost:8000
9) 승인키 발급
10) .env의 ROAD_ADDRESS_API_KEY에 입력

비고:

- 도로명주소 검색 API는 요청 파라미터로 confmKey를 사용한다.
- 프론트에서 주소검색 팝업을 직접 띄울 계획이 생기면 팝업 API도 별도로 검토한다.
- 현재 프로젝트의 1차 구현은 백엔드에서 검색 API를 호출하는 방식이 적합하다.


4. 건축HUB 건축물대장정보 서비스
-------------------------------

용도:

- 기존 건축물 정보 조회
- 주용도/세부용도
- 연면적/건축면적/층수
- 대지위치
- 건축물대장 기반 Building Profile 구성

사이트:

https://www.data.go.kr

신청할 API:

국토교통부_건축HUB_건축물대장정보 서비스

신청 절차:

1) 공공데이터포털 접속
2) 회원가입 또는 로그인
3) 검색창에서 "국토교통부_건축HUB_건축물대장정보 서비스" 검색
4) 해당 OpenAPI 상세 페이지 진입
5) 활용신청 선택
6) 개발계정 신청
7) 활용 목적 입력
   예: AI 건축 인허가 사전진단 서비스 개발을 위해 PNU/대지위치 기반 건축물대장 속성정보를 조회하고, 기존 건축물 용도/면적/층수/지역지구 정보를 진단 입력값으로 활용합니다.
8) 승인 후 마이페이지 또는 API 활용내역에서 일반 인증키 확인
9) .env의 BUILDING_HUB_API_KEY에 입력

비고:

- 공공데이터포털 키는 서비스별 활용신청 승인이 필요하다.
- 키 문자열이 같더라도 승인받지 않은 API는 호출이 실패할 수 있다.
- 현재 테스트에서는 BUILDING_HUB_API_KEY로 건축물대장정보 serviceKey 인증 통과를 확인했다.


5. 건축HUB 건축인허가정보 서비스
-------------------------------

용도:

- 건축 인허가 정보 조회
- 기존 인허가 이력 참고
- 유사 인허가 사례 확장
- 프로젝트 상세/진단 이력 고도화

사이트:

https://www.data.go.kr

신청할 API:

국토교통부_건축HUB_건축인허가정보 서비스

신청 절차:

1) 공공데이터포털 접속
2) 로그인
3) "국토교통부_건축HUB_건축인허가정보 서비스" 검색
4) OpenAPI 상세 페이지 진입
5) 활용신청 선택
6) 개발계정 신청
7) 활용 목적 입력
   예: 건축 인허가 사전진단 결과의 참고 정보와 유사 인허가 이력 분석을 위해 건축HUB 건축인허가정보를 조회합니다.
8) 승인 후 기존 공공데이터포털 인증키로 호출 가능 여부 확인

현재 상태:

- 사용자가 공유한 스크린샷 기준으로 신청자는 이미 승인 상태로 보인다.
- 다만 .env에는 별도 BUILDING_PERMIT_HUB_API_KEY가 없다.
- 공공데이터포털은 일반적으로 계정의 serviceKey를 활용하되 API별 활용신청 승인이 필요하므로, 같은 BUILDING_HUB_API_KEY를 사용하되 API client 내부에서 endpoint만 분리하는 방식이 적합하다.
- 나중에 키를 명확히 분리하고 싶다면 .env.example에 BUILDING_PERMIT_HUB_API_KEY를 추가할 수 있다.


6. 국가법령정보 공동활용 Open API
--------------------------------

용도:

- 건축법, 국토계획법, 농지법, 산지관리법 등 법령 검색
- 시행령/시행규칙 검색
- 행정규칙 검색
- 자치법규/조례 검색
- RAG 원천 문서 수집

사이트:

https://open.law.go.kr

신청 절차:

1) 국가법령정보 공동활용 사이트 접속
2) 사용자 가입
3) 가입 과정에서 openAPI 신청 항목 선택
4) API인증키(OC) 입력
   - 이 사이트는 사용자가 OC 값을 직접 정하는 방식으로 안내된다.
   - 예: redpermit2026
5) 시스템명 입력
   예: AI 건축 인허가 매니저
6) 시스템 설명 입력
   예: 건축 인허가 사전진단을 위한 법령/조례/행정규칙 근거 검색 및 RAG 구축
7) 도메인 또는 서버 정보 입력
   - 개발 중이면 localhost 또는 추후 배포 도메인
8) 공동활용 법령 종류 선택
   - 법령
   - 행정규칙
   - 자치법규
   - 판례/해석례/행정심판례는 대안 시나리오 단계에서 필요하면 추가 검토
9) 신청 후 API인증키관리에서 OC 확인
10) .env의 LAW_OPEN_API_KEY에 입력

비고:

- 국가법령정보 API는 호출 시 OC 파라미터를 사용한다.
- 법령명, 조문번호, 시행일, 수집일을 EvidenceChunk metadata로 남기는 설계가 필요하다.


7. OpenAI API Key
-----------------

용도:

- 체크리스트 문장 생성
- 사전협의 질문 생성
- 대안 시나리오 설명 생성
- 보고서 문장 생성
- Structured Output 기반 정형 결과 생성

사이트:

https://platform.openai.com

신청 절차:

1) OpenAI Platform 접속
2) 로그인
3) 결제 정보 등록
   - ChatGPT Plus와 API 결제는 별도다.
4) API Keys 페이지 이동
   - https://platform.openai.com/api-keys
5) Create new secret key 선택
6) 이름 입력
   예: red-local-dev
7) 생성된 키를 즉시 복사
8) .env의 OPENAI_API_KEY에 입력

비고:

- API 키는 생성 시 한 번만 전체 값이 보인다.
- 키를 Git에 올리면 안 된다.
- 프론트엔드 .env에 넣으면 브라우저에 노출되므로 절대 넣지 않는다.
- 운영 시에는 사용량 제한, 결제 한도, 프로젝트별 키 분리를 권장한다.


8. 현재 신청하지 않았거나 추후 검토할 수 있는 API
-----------------------------------------------

8.1 이미 신청한 것으로 보이는 것

- 국토교통부_건축HUB_건축인허가정보 서비스
  - 스크린샷 기준 승인 상태로 보인다.
  - 다만 현재 .env에는 별도 키 이름이 없다.
  - 향후 building_hub_client와 permit_history_client를 분리할지 결정하면 된다.

8.2 아직 필수는 아니지만 향후 검토할 수 있는 것

- 자치법규/조례 데이터
  - 국가법령정보 공동활용 범위 또는 별도 자치법규 API 제공 범위를 확인해야 한다.
  - 지자체별 조례 최신성 관리가 중요하다.

- 지구단위계획 PDF 원문
  - 별도 단일 API로 해결되기 어렵다.
  - 지자체 고시/공고, 도시계획 포털, PDF 수집 정책이 필요하다.

- 행정심판례/질의회신/법령해석례
  - 대안 시나리오와 참고사례 검색에 필요하다.
  - 국가법령정보 공동활용에서 제공되는 범위와 호출 제한을 확인해야 한다.

- 소셜 로그인 API
  - IA에는 소셜 로그인 영역이 있으나 MVP 핵심은 아니다.
  - Google/Naver/Kakao 로그인은 실제 회원/조직 기능을 구현할 때 별도 신청한다.

- 지도 타일/상용 지도 API
  - VWorld 중심으로 충분하면 추가 신청은 필요 없다.
  - UX 개선을 위해 Kakao/Naver 지도 검색을 쓰려면 별도 키가 필요하다.


9. 팀원별 신청 체크리스트
------------------------

각 팀원은 최소 다음을 준비한다.

[ ] VWorld API Key
[ ] 도로명주소 API 승인키
[ ] 공공데이터포털 건축HUB 건축물대장정보 활용신청
[ ] 공공데이터포털 건축HUB 건축인허가정보 활용신청
[ ] 국가법령정보 공동활용 Open API OC
[ ] OpenAI API Key

공유 저장 위치:

- 개인 로컬: 루트 .env
- Git 저장 금지
- 팀 공유가 필요하면 별도 비밀관리 도구 또는 안전한 채널 사용


10. .env 입력 예시
------------------

VWORLD_API_KEY=발급받은_브이월드키
ROAD_ADDRESS_API_KEY=발급받은_도로명주소_승인키
BUILDING_HUB_API_KEY=공공데이터포털_serviceKey
LAW_OPEN_API_KEY=국가법령정보_OC값
OPENAI_API_KEY=sk-...


11. 키 동작 확인 기준
--------------------

키를 넣은 뒤 최소 확인할 것:

- VWorld: 주소 좌표 변환 또는 지도 API 호출 성공
- 도로명주소: 검색 API errorCode 0 또는 정상 응답
- 건축HUB: 실제 serviceKey 인증 시 HTTP 200
- 국가법령정보: 건축법 검색 결과 반환
- OpenAI: models endpoint 또는 간단한 responses 호출 성공

주의:

- 공공데이터포털은 키가 맞아도 활용신청하지 않은 API는 실패할 수 있다.
- 테스트 대상 필지에 데이터가 없으면 HTTP 200이지만 본문이 비어 있을 수 있다.
- 이 경우 인증 실패와 데이터 없음은 구분해서 봐야 한다.
