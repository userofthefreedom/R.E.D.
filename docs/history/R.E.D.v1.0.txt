1. 오늘 정리한 기준 문서
-----------------------

다음 문서를 기준으로 현재 프로젝트 방향과 구조를 재정렬했다.

- docs/planning/AI_건축_인허가_매니저.docx
- docs/planning/IA&wireframe.pdf
- docs/architecture/AI_건축_인허가_매니저_프로젝트_구조_설계안.txt

핵심 방향은 다음과 같다.

- 본 서비스는 단순 LLM 챗봇이 아니다.
- 주소 문자열이 아니라 PNU, 필지 Geometry, Parcel Profile, Building Profile, Action JSON을 기준으로 판단한다.
- 핵심 판단은 LLM이 아니라 룰엔진이 담당한다.
- RAG는 법령, 조례, 지구단위계획 근거를 Evidence Trace로 연결한다.
- LLM은 체크리스트, 사전협의 질문, 보고서 문장 생성 보조자로 제한한다.
- 최종 결과는 관할 행정청 판단을 대체하지 않는 사전진단 참고자료로 제공한다.

3. 현재까지 된 것
----------------

현재 프로젝트는 다음 상태다.

- 기획서, IA, 구조 설계안의 방향성은 프로젝트 구조에 반영되어 있다.
- 프론트엔드는 회의에서 화면 흐름을 확인할 수 있는 mockup 단계까지 구현되었다.
- 백엔드는 endpoint 구조와 파일 경계가 잡힌 스캐폴딩 단계다.
- 인프라 구성 파일은 있다.
  - PostgreSQL/PostGIS
  - Redis
  - Qdrant
- API 키는 1차 개발에 필요한 핵심 키가 준비되어 있다.
- 룰엔진, RAG, LLM, 문서 생성 서비스는 아직 대부분 pass 또는 스텁 상태다.
- DB 모델, migration, repository, 실제 CRUD는 아직 구현 전이다.

7. 중요한 주의사항
-----------------

- .env는 Git에 올리지 않는다.
- API 키는 프론트엔드 .env에 넣지 않는다.
- LLM이 인허가 가능/불가를 직접 판단하게 만들지 않는다.
- 법령 설명은 반드시 Evidence Trace와 연결되도록 설계한다.
- 정보 부족, API 실패, 조례 최신성 미확인 상황에서는 단정하지 않고 추가정보 필요 또는 관할부서 확인 필요로 표시한다.
