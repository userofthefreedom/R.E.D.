# Codex 참고문서
# AI 건축 인허가 매니저 프로토타입 업그레이드 요구사항

## 1. 프로젝트 개요

`AI 건축 인허가 매니저`는 위치 기반 공공데이터, 룰엔진, RAG, LLM 문서 생성을 결합한 건축 인허가 사전진단 웹 서비스다.

사용자는 주소, 지번, 좌표 또는 지도 클릭으로 대상지를 선택하고, 신축/증축/용도변경/대수선 등 건축계획을 입력한다. 시스템은 대상지를 PNU와 필지 Polygon으로 식별하고, 건축물대장·토지이용계획·VWorld·공간규제·법령·조례·지구단위계획 정보를 바탕으로 조건부 절차, 제출자료, 사전협의 쟁점, 예상 리스크를 정리한다.

핵심은 LLM이 임의로 판단하는 것이 아니라 다음 역할 분리를 따르는 것이다.

- 공공데이터: 대상지/건축물/토지이용/공간규제 조회
- 룰엔진: 명시적 조건 기반 절차 판별
- RAG: 법령·조례·지구단위계획 근거 검색
- LLM: 체크리스트, 사전협의 질문, 신청서 초안, 보고서 문장 생성
- Trace: Rule Trace와 Evidence Trace로 판단 근거 추적

프로토타입에서는 실제 API 연동 대신 mock data를 사용하되, 이 구조가 화면에 드러나야 한다.

첨부 발표 PDF의 분위기는 다음과 같다.

- 부동산 개발/건축/시공 맥락
- 차분한 블루 계열
- 건축 현장, 크레인, 건물, 구조물 이미지

## 4. 화면별 상세 요구사항

## 4.1 프로젝트 대시보드

목적:

- 사용자가 진행 중인 진단, 저장된 보고서, 최근 알림을 한눈에 확인한다.
- 새 진단 시작으로 자연스럽게 진입한다.

필수 요소:

- 전체 프로젝트 수
- 진행 중 진단 수
- 저장된 보고서 수
- 최근 알림 수
- 프로젝트 목록
- 최근 진단
- 저장된 보고서
- 새 진단 시작 버튼

상태별 액션:

| 상태 | 액션 |
|---|---|
| 진단 진행중 | 이어하기 |
| 판정 완료 | 결과 보기 |
| 보고서 생성됨 | 다운로드 |
| 추가정보 필요 | 보완하기 |
| 오류 | 다시 시도 |

## 4.2 위치 입력 및 PNU 변환

목적:

- 주소/지번/좌표/지도 클릭으로 정확한 대상지를 선택한다.
- 모든 판단의 기준이 되는 PNU와 필지 Polygon을 확정한다.

필수 요소:

- Wizard stepper
- 지도 영역
- 주소 / 지번 / 좌표 검색 탭
- PNU 후보 목록
- 선택된 대지 정보
- 데이터 기준일자
- 공공데이터 조회 상태
- 공간규제 레이어 토글
- 이전/다음 버튼

```ts
type PnuCandidate = {
  pnu: string;
  standardAddress: string;

  landCategory: string;
  siteArea: number;
  matchScore: number;

```

```ts
{
  standardAddress: "서울특별시 강남구 테헤란로 123",
  jibunAddress: "역삼동 123-45",
  legalDongCode: "1168051000",
  pnu: "41287-10123-0123456",
  landCategory: "대",
  siteArea: 540.0,
  useDistrict: "제2종일반주거지역",
  districtUnitPlan: false,
  dataBaseDate: "2025-05-20"
}
```

## 4.3 건축 계획 입력 및 정규화

목적:

- 사용자의 사업 계획을 법률 판단 가능한 구조로 정규화한다.
- 사용자의 입력이 Action JSON으로 바뀌는 과정을 투명하게 보여준다.

필수 입력:

| 그룹 | 필드 |
|---|---|
| 기본 행위 정보 | 행위 유형, 현재 용도, 희망 용도, 기존 건축물 여부 |
| 규모/면적 정보 | 대지 면적, 건축면적, 연면적, 층수, 주차대수 변경 전/후 |
| 현장 조건 | 성토/절토, 도로 접도, 도로 폭 확인, 주차 변경, 진입로 확보, 지구단위계획 검토 필요 |
| 추가 입력 정보 | 공사 방식, 특이사항 메모, 사업 목적 요약 |

오른쪽 패널:

- 법률 판단용 문장 미리보기
- Action JSON 요약
- 누락정보 / 검증 알림
- 용도 선택 가이드

Action JSON 예시:

```json

  "totalFloorArea": 1200.0,
  "floorCount": {
    "aboveGround": 5,
    "underground": 0
  },
  "parkingBefore": 0,
  "parkingAfter": 12,
  "siteConditions": {
    "earthwork": false,
    "roadAccess": true,
    "roadWidthCheck": true,
    "parkingChange": true,
    "accessRoadSecured": true,
    "districtPlanReview": false
  },
  "constructionMethod": "일반 신축",
  "memo": "기존 토지 매입 후 업무시설 신축 검토",
  "businessPurpose": "사무실 및 근린생활시설 복합 개발"
}
```

## 4.4 판정 결과 및 근거 확인

목적:

- 진단 결과를 보여주는 핵심 화면이다.
- 사용자가 결과를 신뢰할 수 있도록 근거와 판단 경로를 함께 제공한다.

필수 카드:

- 종합 판정
- 주 인허가 유형
- 리스크 레벨
- 누락정보 개수

필수 표:

조건부 절차 목록

| 절차명 | 대상 여부 | 판단 사유 | 담당 부서 | 리스크 |
|---|---|---|---|---|
| 건축허가 | 대상 | 신축 및 연면적 조건에 따라 건축허가 검토 필요 | 건축과 | 보통 |
| 개발행위허가 | 조건부 | 대지 현황 및 도로 접도 조건 추가 확인 필요 | 도시계획과 | 중간 |
| 교통영향평가 | 조건부 | 연면적 및 용도에 따라 교통량 검토 필요 | 교통과 | 중간 |
| 경관심의 | 비대상 | 현재 공간규제 중첩 없음 | 경관과 | 낮음 |
| 주차장 조례 검토 | 대상 | 용도변경/신축 시 주차대수 기준 확인 필요 | 교통과 | 보통 |

근거 패널 탭:

1. 법령/조례 근거
2. Evidence Trace
3. Rule Trace

메타 정보:

```ts
{
  dataBaseDate: "2025-05-20",
  lawBaseDate: "2025-05-20",
  ruleSetVersion: "rule-set-v0.1.0",
  ragIndexVersion: "legal-index-v0.1.0"
}
```

Evidence Trace 예시:

```ts
{
  procedure: "개발행위허가",
  source: "국토의 계획 및 이용에 관한 법률 제56조",
  chunkId: "LAW-NLPA-56-001",
  reason: "토지의 형질변경 및 개발행위 허가 대상 여부 판단 근거",
  confidence: 0.87
}
```

Rule Trace 예시:

```ts
{
  ruleId: "DEV-ACT-001",
  ruleName: "개발행위허가 검토 룰",
  inputFields: ["action.actionType", "parcel.landCategory", "siteConditions.roadAccess"],
  result: "조건부 검토",
  reason: "신축 계획과 대지 조건에 따라 개발행위허가 검토 필요"
}
```

## 4.5 대안 시나리오 탐색

목적:

- 저가능성 또는 고위험 판단 시 사용자가 대안을 검토할 수 있게 한다.
- 단순히 “불가”가 아니라 조정 가능한 의사결정 옵션을 제공한다.

필수 요소:

- 결과 화면으로 복귀
- 리스크 원인 분석
- 현재 판단 요약
- 유사 인허가 사례
- 대안 비교
- 권장 다음 행동
- 보고서 반영

유사 사례 예시:

```ts
[
  {
    title: "강남구 근린생활시설 신축 검토 사례",
    similarity: 85,
    region: "서울 강남구",
    useDistrict: "제2종일반주거지역",
    landCategory: "대",
    result: "조건부 승인",
    referencePoint: "주차대수 보완 및 도로 접도 확인 후 진행"
  },
  {
    title: "송파구 업무시설 용도변경 사례",
    similarity: 78,
    region: "서울 송파구",
    useDistrict: "일반상업지역",
    landCategory: "대",
    result: "사전협의 후 보완",
    referencePoint: "교통량 검토와 부서 협의 선행"
  }
]
```

대안 비교 예시:

| 대안 | 기대효과 | 한계 | 협의 포인트 |
|---|---|---|---|
| 연면적 축소 | 교통영향 및 주차 부담 완화 | 사업성 저하 가능 | 건축과, 교통과 |
| 일부 용도 조정 | 허용용도 충돌 완화 | 수익 구조 변경 필요 | 도시계획과 |
| 주차계획 보완 | 주차장 조례 리스크 완화 | 추가 비용 발생 | 교통과, 건축과 |

## 4.6 실무 산출물 생성

목적:

- 진단 결과를 실제 사전협의와 내부 보고에 활용 가능한 문서로 만든다.

산출물:

- 절차별 체크리스트
- 필요서류 목록
- 담당부서별 사전협의 질문
- 신청서/신고서 초안
- 종합 보고서

진행 상태:

1. 보고서 컨텍스트 구성 중
2. 근거 정리 중
3. 문서 생성 중
4. 다운로드 준비 완료

면책 문구:

> 본 서비스에서 생성되는 모든 산출물은 건축 인허가 접수 전 사전진단 참고자료입니다. 최종 인허가 여부는 관할 행정청의 검토와 최신 법령·조례 적용에 따라 결정됩니다.

필수 요소:

- "검토 중인 사전진단을 한눈에 확인"
- "프로젝트 상태, 저장 보고서, 최근 알림, 이어하기 액션을 mock 데이터로 구성했습니다."
- "새 진단 시작"

### 위치 입력

- "위치 입력 및 PNU 변환"
- "주소, 지번, 좌표 또는 지도 클릭으로 대상지를 선택하세요."
- "공공데이터 조회 상태: 정상"
- "기준일자: 2025-05-20"

### 건축 계획 입력

- "건축 계획 입력 및 정규화"
- "입력한 계획은 법률 판단용 문장과 Action JSON으로 변환됩니다."
- "누락된 정보는 진단 전 검증됩니다."

### 결과 화면

- "판정 결과 및 근거 확인"
- "룰엔진 판단과 RAG 근거를 함께 확인하세요."
- "적용 룰셋"
- "법령 기준일"
- "Evidence Trace"
- "Rule Trace"

### 대안 시나리오

- "대안 시나리오 탐색"
- "저가능성 또는 고위험 판단일 때 결과 화면에서 분기되는 보조 의사결정 화면입니다."
- "보고서에 반영"

### 산출물

- "실무 산출물 생성"
- "체크리스트, 필요서류, 사전협의 질문, 신청서 초안, 종합 보고서를 생성합니다."
- "DOCX 다운로드"
- "PDF 다운로드"

## 7. 구현 시 주의사항

- 실제 법률 판단처럼 보이되, 확정적 표현은 피한다.
  - "허가 가능"보다 "조건부 가능성", "추가 검토 필요", "사전협의 권장" 사용
- 모든 결과에는 기준일자와 출처/근거 느낌을 준다.
- 대안 시나리오는 확정 승인 가능성을 의미하지 않는다고 안내한다.
- 화면이 발표 자료와 함께 보일 것이므로 색상과 여백을 정돈한다.
- 사용자가 한 번의 시연으로 서비스 가치를 이해할 수 있게 한다.
- 복잡한 내용을 감추지 말고, 카드/탭/표로 정리해 신뢰성을 보여준다.
